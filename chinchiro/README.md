# チンチロ（飲み会用）

各自のスマホでログインして、グループで順番にサイコロを振るチンチロアプリです。
出目はグループごとに最新1000ターンまで保存され、期間を選んで個人別・役別に分析できます。

## できること

| 画面 | 内容 |
|---|---|
| プレイ | 手番の人が「サイコロを振る」。役が出るまで最大3投。全員の画面にリアルタイムで同じ出目が出る |
| 周の結果 | 全員が振り終わると、順位（最強・最弱）を全員の画面に表示 |
| 代わりに振る / スキップ | 手番の人が席を外しているとき、他の人が代理で振る、または今回だけ飛ばす |
| 休憩 | メンバータブでスイッチをオンにすると、戻るまで自動で順番を飛ばす |
| 記録 | 周ごとの出目（振り直しの途中経過も含む）を一覧表示 |
| 分析 | 期間（今日・昨日・直近100回・直近10周・今週・先週・今月・全期間・期間指定）を選んで集計 |

分析タブの中身：

- **概要**：役の出現率（理論値と比較）、注目ポイント（アラシ王、ヒフミ2連続、ピンゾロ達成など）、最強・最弱の回数
- **個人**：偏りレポート（理論値より多い／少ない役を統計的に判定）、役の出現率、サイコロの目（1〜6）の偏り検定、連続記録（「ヒフミの次もヒフミ」率など）、最近の出目、対戦成績
- **ランキング**：役ごと（シゴロ・アラシ・ヒフミ…）、最強率・最弱率、1投目決着率、連続系、サイコロの目など約30の切り口で、確率の高い順に並べる
- **対戦**：メンバー同士の勝ち-負け表

※ 1日の区切りは**朝5時**です（深夜まで続く飲み会が「今日」に入るように）。

## ルール

役の強さ（上ほど強い）：

1. ピンゾロ（1・1・1）
2. アラシ（2〜6のゾロ目。数字が大きいほど強い）
3. シゴロ（4・5・6）
4. 目（2つ同じ＋1つ違う → 違う1つの数字が「目」。6の目が最強、1の目が最弱）
5. 目なし（3投しても役が出ない）
6. ションベン（設定でオンにしたときだけ。サイコロがどんぶりから出て即負け）
7. ヒフミ（1・2・3）

サイコロはサーバー側で暗号論的乱数（`crypto.randomInt`）で決めるので、誰の端末で振っても公平です。

## 手元のパソコンで動かす

Node.js 20 以上が必要です。

```bash
cd chinchiro
npm install
npm start
```

ブラウザで http://localhost:3000 を開きます。データは `chinchiro/data/` フォルダにJSONで保存されます。

## インターネットに公開する（無料プランの例：Render + Neon）

飲み会でスマホから使うには、インターネット上に置く必要があります。ここでは
**Render**（アプリを動かすサーバー）と **Neon**（データを保存するデータベース）を使う手順を説明します。
どちらも無料プランがあります（2026年10月時点。画面の文言は変わることがあります）。

> なぜデータベースが要るのか：Render の無料サーバーは再起動のたびにファイルが消えるため、
> 記録を残すには外部のデータベース（PostgreSQL）に保存する必要があります。

### 1. Neon でデータベースを作る

1. https://neon.tech を開き、右上の **Sign up** から GitHub アカウントで登録する
2. 最初の画面（Create project）で
   - **Project name**：`chinchiro` など好きな名前
   - **Region**：日本に近いもの（例：AWS Asia Pacific (Singapore)）
   - **Create project** を押す
3. ダッシュボードの **Connect** ボタンを押す
4. 表示された接続文字列（`postgresql://` で始まる1行）の **Copy** を押してメモ帳に貼っておく
   - これがパスワード入りの「合い鍵」です。人に見せないでください

### 2. Render でアプリを公開する

1. https://render.com を開き、**Get Started** → GitHub アカウントで登録する
2. ダッシュボード右上の **+ New** → **Web Service** を選ぶ
3. **Git Provider** で GitHub を選び、リポジトリ `hamagin_ri` の **Connect** を押す
   （初回は GitHub 側で Render にリポジトリへのアクセスを許可する画面が出ます）
4. 設定画面で次のように入力する

   | 項目 | 入力する値 |
   |---|---|
   | Name | `chinchiro`（URLの一部になります） |
   | Language | **Docker** |
   | Branch | このアプリがあるブランチ（マージ後は `main`） |
   | Region | **Singapore** |
   | Root Directory | `chinchiro` |
   | Instance Type | **Free** |

5. 下の **Environment Variables** で **Add Environment Variable** を押し、
   - NAME：`DATABASE_URL`
   - VALUE：手順1でコピーした接続文字列
6. 一番下の **Deploy Web Service** を押す
7. ログに `チンチロ起動` と出たら完了。画面上部の `https://chinchiro-xxxx.onrender.com` が公開URLです

### 3. 使い始める

1. 公開URLをスマホで開き、**新規登録**（ログインID・表示名・パスワード）
2. **グループを作る** → メンバータブの **リンクを送る** で LINE などに招待リンクを共有
3. みんなが参加したら **プレイ** タブで順番に振る

ホーム画面に追加（iPhone：共有ボタン →「ホーム画面に追加」）するとアプリのように使えます。

### 無料プランの注意

- Render の無料サーバーは **15分アクセスがないと眠り**、次に開いたとき起動まで1分ほどかかります。飲み会の前に一度開いておくと安心です
- パスワードを忘れた場合の再発行機能はありません（新しいIDで登録し直してください）

### ほかのサービスで動かす場合

- Docker が動くサービスならどこでも動きます（環境変数 `PORT` に対応）
- **サーバーは必ず1台で動かしてください**（ゲームの進行状態をメモリで持っているため）。
  Google Cloud Run なら `--max-instances=1 --session-affinity` を付けます
- `DATABASE_URL` を設定しない場合は `DATA_DIR`（既定は `./data`）にJSONで保存します。
  永続ディスクがあるサービスなら、そのディスクを `DATA_DIR` に指定すればデータベースなしでも使えます

## 設定（環境変数）

| 変数 | 内容 | 既定値 |
|---|---|---|
| `PORT` | 待ち受けるポート | `3000` |
| `DATABASE_URL` | PostgreSQL の接続文字列。設定するとデータベースに保存 | なし |
| `DATA_DIR` | `DATABASE_URL` がないときの保存先フォルダ | `./data` |

## テスト

```bash
npm test        # 役判定・理論確率・ゲーム進行・分析のユニットテスト
npm run e2e     # ブラウザ（Playwright）で3人同時プレイ→分析→再起動後のデータ保持まで通しで確認
```
